## 0. ГЛАВНЫЕ ПРАВИЛА (приоритет выше всех остальных)

1. **Работаем маленькими шагами.** Один шаг — одна небольшая законченная часть (одна таблица, один экран, одна функция). Не пиши сразу несколько экранов или модулей.
2. **Тесты — часто.** После каждого шага, который можно проверить, нужен тест. Лучше слишком много проверок, чем мало.
3. **ПАУЗА ПЕРЕД КАЖДЫМ ТЕСТОМ.** Перед любым запуском теста (автоматического или ручного) ты **останавливаешься и ждёшь подтверждения пользователя**. Порядок строго такой:
   1. Закончи код шага.
   2. Напиши блок паузы (формат в разделе 1).
   3. **Прекрати работу.** Не запускай тесты, не пиши следующий код, не вызывай инструменты.
   4. Продолжай только после ответа пользователя: «продолжай», «ок» или результат теста.
4. **Не запускай тесты сам без разрешения**, даже если они быстрые, а команда кажется безобидной. Исключение одно: проверка синтаксиса `python -m py_compile <файл>` можно выполнять без паузы.
5. **Не переходи к следующему этапу**, пока пользователь не подтвердил, что тест текущего пройден.
6. **Если тест упал** — объясни причину, предложи исправление, внеси его и снова сделай паузу перед повторным тестом.
7. **Не выдумывай требования.** Всё, чего нет в этом файле, не реализуй. Если что-то неясно, задай один короткий вопрос и жди ответа.
8. **Git:** после каждого пройденного теста предложи коммит (сообщение на русском, в формате `этап N: что сделано`). Коммить только после подтверждения пользователя.

## 2. О ПРОЕКТЕ

Десктопное приложение «Информационная система для магазина настольных игр». Курсовой проект колледжа ВятГУ.

**Стек (менять нельзя):**
- Python 3.11+
- PyQt6 (графический интерфейс)
- PostgreSQL (база данных), драйвер `psycopg2-binary`
- Git, Visual Studio Code / Cursor
- Тесты: `pytest`

**Три роли:**
| Роль | Код в БД | Возможности |
|---|---|---|
| Пользователь (клиент) | `client` | каталог, карточка товара, избранное, корзина, заказ, профиль, «Мои заказы» |
| Работник | `employee` | управление товарами, заказами, поставщиками, свой профиль |
| Администратор | `admin` | всё, что у работника, плюс управление пользователями |

Администратор — это работник с расширенными правами.

**Правила учётных записей:**
- Самостоятельная регистрация доступна **только клиентам**.
- Работников и администраторов создаёт только администратор в разделе «Пользователи».
- Логин — адрес электронной почты.
- Первого администратора создаёт отдельный скрипт `scripts/create_admin.py`.

## 4. БАЗА ДАННЫХ (PostgreSQL)

Минимальный набор таблиц. Названия можно уточнить, состав — нет.

- `users` — id, email (уникальный), password_hash, name, phone, avatar_path, role (`client`/`employee`/`admin`), status (`active`/`blocked`), created_at
- `categories` — id, name (жанры)
- `products` — id, name, description, price, quantity, image_path, category_id, players (количество игроков), play_time (время игры), age (возраст)
- `favorites` — user_id, product_id (составной ключ)
- `cart_items` — user_id, product_id, quantity
- `orders` — id, user_id, status (`Новый`/`В обработке`/`Доставленный`), total, created_at
- `order_items` — order_id, product_id, quantity, price
- `suppliers` — id, name, email, phone, status
- `supplier_products` — supplier_id, product_id

Требования:
- Внешние ключи, `NOT NULL`, `CHECK (price >= 0)`, `CHECK (quantity >= 0)`.
- Пароли хранятся **только в виде хеша** (`bcrypt` или `hashlib.pbkdf2_hmac` с солью).
- Для тестов используется **отдельная база** `board_games_test`, рабочую базу тесты не трогают.

## 5. ЭКРАНЫ И ТРЕБОВАНИЯ К ИНТЕРФЕЙСУ

Стиль простой и понятный, тёмная подложка в окнах входа и регистрации. Переключатель светлой и тёмной темы в профиле. Боковая панель слева, содержимое справа.

**Общие для всех:**
1. **Окно входа:** логотип, поля «Электронная почта» и «Пароль» (скрытый ввод), кнопка «Войти», ссылка «Нет аккаунта? Зарегистрироваться».
2. **Окно регистрации:** логотип, «Электронная почта», «Пароль», «Подтверждение пароля», флажок «Согласие на обработку персональных данных» (без него регистрация невозможна), кнопка «Зарегистрироваться», ссылка «Уже есть аккаунт? Войти».

**Клиент** (боковая панель: логотип, кнопка с аватаром и именем → профиль, «Главная», «Каталог», «Корзина», «Избранное», «Выйти»):
3. **Главная:** баннер «Настольные игры для всей семьи» с кнопкой «Перейти в каталог», блок «Популярные игры» с карточками (изображение, название, «Добавить в избранное»).
4. **Каталог:** строка поиска (по названию и описанию), фильтры-выпадающие списки «Количество игроков», «Время игры», «Возраст», блок «Категории» кнопками-жанрами, карточки товаров.
5. **Избранное:** строка поиска и карточки добавленных игр.
6. **Корзина:** таблица (изображение, название, цена, количество с возможностью изменить, действия — удалить), кнопка «Очистить корзину», блок «Итого» (количество и сумма), кнопка «Заказать».
7. **Карточка товара:** изображение, название, цена, блок краткой информации (время игры, возраст, игроки), выбор количества (кнопки «+», «−» и ручной ввод), «Добавить в корзину», блок «Описание», переключатель «Добавить в избранное».
8. **Профиль:** аватар, поля «Имя», «Телефон», «Электронная почта» (почта только для просмотра), «Изменить аватар», переключатель темы, кнопка «Мои заказы».
9. **Окно «Ваши заказы»** (всплывающее): столбцы ID, Содержимое, Сумма, Статус, Дата заказа, кнопка «Удалить заказ».

**Работник / администратор** (боковая панель: «Товары», «Заказы», «Пользователи» — только админу, «Поставщики», «Выйти»):
10. **Управление товарами:** поиск по названию, фильтры «Категория» и «Цена», кнопка «Добавить товар», таблица (ID, изображение, название, категория, цена, количество — при нуле надпись «Нет в наличии», действия: редактировать и удалить).
11. **Заказы:** вкладки «Все», «Новые», «В обработке», «Доставленные», поиск, сортировка по дате, кнопка «Добавить заказ», таблица (ID, пользователь, содержание, сумма, статус, дата, действия).
12. **Поставщики:** поиск по названию, фильтр по статусу, кнопка «Добавить поставщика», таблица (ID, название, почта, телефон, поставляемые товары, статус, действия).
13. **Пользователи (только администратор):** поиск, сортировка по роли и по статусу, «Добавить пользователя», таблица (ID, имя, почта, телефон, аватар, роль, статус, действия).
14. **Профиль работника:** как у клиента, но вместо заказов блок «Роль и права доступа».

**Проверка данных:**
- Нельзя сохранить запись с пустыми обязательными полями или недопустимыми значениями (отрицательная цена, нечисловое количество, некорректная почта).
- Ошибки пользователя показываются понятным сообщением, после чего программа возвращается в рабочее состояние. Приложение не должно падать.
- Все операции выполняются через графический интерфейс.

## 7. КАК ОТЧИТЫВАТЬСЯ ПОСЛЕ ТЕСТА

Когда пользователь прислал результат теста:
1. Если тест прошёл — одной строкой подтверди, предложи коммит, затем начни следующий шаг.

3. Не меняй код, не относящийся к упавшему тесту.
