# Демонстрация информационной системы на защите

## Сценарий на 5–7 минут

Подготовить демонстрационную БД, три разные учётные записи, игру с остатком и папку для чека. Установить шрифт DejaVu Sans. Использовать вымышленные контактные данные.

1. **30 секунд.** Назвать тему, цель и роли. Показать окно входа и обязательное согласие при регистрации.
2. **90 секунд.** Войти как покупатель. Найти игру фильтрами, открыть карточку, добавить товар в избранное и в корзину. Показать количество и итог.
3. **60 секунд.** Оформить заказ, в профиле открыть список заказов и сохранить чек. Открыть PDF, сверить цену, количество и итог.
4. **90 секунд.** Войти как работник, найти заказ, перевести в обработку. Показать уменьшившийся остаток товара и поставщика с ассортиментом.
5. **60 секунд.** Войти как администратор. Показать раздел пользователей и блокировку отдельной демонстрационной записи.
6. **30–60 секунд.** Показать ER-диаграмму и объяснить, что проверка остатка и запись заказа выполняются в одной транзакции.

## Вопросы к защите

**Почему PostgreSQL?** Внешние ключи и ограничения помогают сохранять согласованность записей. Транзакции и блокировки строк позволяют одновременно оформлять заказы без двойного списания одного остатка.

**Как распределены обязанности между модулями?** Окна отвечают за ввод и отображение, сервисы проверяют правила и права, репозитории хранят SQL и выполняют транзакции.

**Зачем отдельная таблица поставщиков и товаров?** Одна игра может поступать от разных поставщиков. У каждого поставщика может быть много игр. Таблица связей хранит по одной строке на пару.

**Как хранится пароль?** База хранит bcrypt-хеш с солью. При входе введённое значение проверяется функцией bcrypt.checkpw.

**Как клиент защищён от просмотра чужого заказа?** Сервис требует право на операцию и ограничивает запрос идентификатором текущего пользователя. Запрет действует при прямом вызове сервиса.

**Что происходит при нехватке товара?** Транзакция блокирует проверяемые строки. Если хотя бы один остаток меньше требуемого, изменения откатываются и корзина сохраняется.

**Почему цена есть и в товаре, и в позиции заказа?** Цена товара используется для новых покупок. Цена позиции сохраняется на момент оформления и нужна для истории и чека.

**Как считается сумма?** Цена умножается на количество в каждой позиции, результаты суммируются. Для денег используется Decimal. Итоговое количество — сумма количеств позиций.

**Где хранится чек?** При скачивании PDF строится из заказа и позиций и сохраняется по выбранному пользователем пути. В базе хранятся исходные записи.

**Что сделано для защиты персональных данных?** Для входа требуется активная учётная запись. Права ограничены по ролям. Локальный кластер слушает петлевой адрес, регистрация требует согласия, журнал не хранит введённые реквизиты.

## Комплект перед защитой

- Исходное техническое задание и документы из папки `docs`.
- Приложение, схема `db/schema.sql`, учебные данные `db/seed.sql`.
- Подготовленные учётные записи, шрифт для PDF и иллюстрации в руководстве.
- Заполненный протокол ПМИ по фактическим результатам.
